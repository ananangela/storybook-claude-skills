# 交付文件規則（deliverable-doc-rules）

給人看的文件是**結論**，不是討論紀錄。五條規則全部是硬規則，任何一條不過就不能交付。

## 適用範圍

- 裁決／決議紀錄（OpenQuestions、Notes 裡的「已決定」、D 編號項目）
- 交接文件（PRODUCTION_HANDOFF、REFERENCE.md、FLOW_SPEC、埋點交接）
- 規格與對照文件（前後對照、進度文件、artifact 頁面、Storybook 的 docs 說明）
- 不適用：程式碼註解、Storybook story 的 JSDoc 導覽文字、與使用者的對話回覆本身

## 五條規則

### 規則 1：不能有建議或模糊地帶

- 文件裡只能有**已定案**的規則。「建議」「可以考慮」「傾向」「較好」「或許」「可能」「應該」「大概」「待定」「待確認」「TBD」「選項 A／B」全部不能出現在定案內容裡。
- 還沒定的事**不是拿掉、也不是自己補一個答案**，而是移到文件最後一節「**人工審核清單**」：每一項寫清楚「哪一處」「兩個以內的候選」「不決定會卡住什麼」，由人決定。清單裡的項目可以用「候選」字眼，其他地方不行。
- 檢查器抓到模糊詞時，只能做兩件事：改成定案句（前提是有定案依據），或搬進人工審核清單。**不能用刪除來讓檢查通過。**

### 規則 2：不能出現使用者與 AI 的溝通過程

- 不寫「使用者說」「使用者指示」「我覺得」「我建議」「你提到」「討論了幾輪」「原本想 A 後來改 B」「稍早曾…作廢」這類過程描述。
- 決策只寫**結果與日期**，例如「取消邀請只取消碼上有你這一層，全站好友關係不變（2026-09-17 定案）」。誰說的、怎麼談的，不進文件。
- 版本演變若有必要保留，放在文件末尾「變更紀錄」一節，一行一條、只寫結果，不寫過程。

### 規則 3：每一顆按鈕的路徑都要明確

文件必須有一張「**互動與跳轉表**」，涵蓋文件提到的每一個可點元素，欄位固定：

| 畫面 | 元素 | 互動方式 | 跳轉／結果 | 條件或狀態 |
|---|---|---|---|---|

- 互動方式：點一下／長按／滑動／系統手勢，以及有無確認彈窗。
- 跳轉／結果：目的頁面名稱（用 Storybook 或 Figma 的正式名稱），或畫面內的具體變化（哪個元素變成什麼、Toast 文字）。
- 條件或狀態：停用條件、上限、只有誰看得到。
- 每一格都要填，填不出來就是規則 1 的模糊地帶，進人工審核清單。
- 文中提到「點 X → Y」的地方，Y 必須是表裡有的目的地。

### 規則 4：假資料聲明

文件開頭（第一節之前或之內）必須有這一段固定聲明，字句可微調但三個要點不能少：

> 本文件與 Storybook 原型中的名單、暱稱、頭像、數字皆為 prototype 假資料（fixtures），**不得**用於正式版；正式版一律接真實資料（API／後端），假資料檔案不進正式程式碼。

### 規則 5：連結與路徑必須是讀者點得到的

- 不能出現：`localhost`、`127.0.0.1`、`~/…`、`/Users/…`、`/private/tmp/…`、`file://`、`C:\…` 這類只有作者電腦看得到的位置。
- 可以出現：Figma 連結、artifact 連結、公開或團隊共用的 Storybook 網址、git 倉庫網址加相對路徑（例如 `app/src/pages/proposals/widget-social/`）、雲端硬碟共用連結。
- 本機才有的參考資料（截圖、影片、工程說明檔）要嘛把內容嵌進文件（圖直接放、重點直接寫），要嘛上傳到共用位置再放連結；兩者都做不到就寫「資料由 {誰} 持有，索取方式：{方式}」。

## 作業流程

1. 寫或改文件前先讀本 Skill。
2. 寫完後執行檢查器：

```bash
python3 ~/.claude/skills/deliverable-doc-rules/scripts/check_doc.py <檔案或資料夾…>
```

   支援 `.md`、`.html`、`.txt`、`.tsx`（只掃字串字面值）。加 `--json` 輸出機器可讀結果。
3. 依報告處理：
   - `[R2] 溝通過程`、`[R4] 缺假資料聲明`、`[R3] 缺互動表`、`[R5] 本機連結`：直接修正。
   - `[R1] 模糊地帶`：能引用既有定案就改寫成定案句；否則搬到「人工審核清單」，並在交付訊息裡把清單**逐條列給使用者**，不能只說「有幾項待確認」。
4. 檢查器回傳 exit code 0 才能發佈／交付；有 `[R1]` 未處理時，交付訊息第一句必須是「有 N 項模糊地帶需要人工審核」。
5. 交付訊息本身也遵守規則 2：只說文件裡有什麼，不重述討論過程。

## 檢查器會抓什麼

- R1 模糊詞（可在 `scripts/ambiguous_terms.txt` 增減）：建議、可以考慮、可考慮、傾向、較好、比較好、或許、可能、也許、應該、大概、看起來、待定、待確認、尚未確認、尚未定案、TBD、TODO、選項①／②、方案 A／B、要不要、是否要、？結尾的句子（人工審核清單一節除外）。
- R2 溝通過程詞：使用者說、使用者指示、使用者認為、使用者提出、我覺得、我建議、我推薦、我偏向、你說、你提到、你覺得、討論了、幾輪、原本想、後來改、稍早曾、作廢、抱歉、誤會、對話、聊到。
- R3：找不到含「互動方式」與「跳轉」欄位的表格；或表格有空格。
- R4：找不到同時含「假資料」（或 fixtures／prototype 資料）與「真實資料」（或 API／後端）的聲明句。

- R5 本機連結：`localhost`、`127.0.0.1`、`~/`、`/Users/`、`/private/tmp`、`/tmp/`、`file://`、`[A-Z]:\`。

檢查器只做提示與阻擋，**不會自動改寫文件內容**。
